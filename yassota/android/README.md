# تطبيق YASSOTA لأندرويد

تطبيق أندرويد رسمي لمنصة يسوتا — غلاف WebView أصلي مرتبط بنفس الـBackend وقاعدة البيانات، مع **Android App Links** فيفتح رابط أي منشور داخل التطبيق مباشرة.

- اسم الحزمة: **`com.yassota.app`** (ثابت — لا يتغيّر أبداً حتى تبقى التحديثات ممكنة)
- minSdk **24** · targetSdk **34**
- توقيع **Release** بمخططي **v2 + v3** (لا Debug)
- بلا Gradle وبلا AndroidX — بناء مباشر بأدوات SDK

## ماذا يفعل التطبيق

- يفتح `https://yassota.com` داخل WebView مُهيّأ (JS، DOM storage لتفضيل المظهر، كوكيز الجلسة).
- **رفع الصور يعمل**: `onShowFileChooser` مربوط بمنتقي الصور — بدونه لا يمكن إنشاء منشور من التطبيق.
- **التنزيلات** تمرّ عبر `DownloadManager` مع ملف تعريف الجلسة.
- **App Links**: رابط `yassota.com/post/...` يفتح داخل التطبيق إن كان مثبتاً، وإلا في المتصفح.
- الروابط الخارجية تُفتح في المتصفح لا داخل التطبيق.
- زر الرجوع يحترم سجل التصفح، وشاشة خطأ واضحة عند انقطاع الشبكة مع زر إعادة محاولة.
- يضيف `YassotaApp/<version>` إلى الـUser-Agent، فيخفي الموقع قسم «حمّل التطبيق» داخل التطبيق نفسه ويعرضه في المتصفح فقط.
- الأذونات المطلوبة فقط: إنترنت، حالة الشبكة، إشعارات (13+)، قراءة الصور (للرفع). **لا موقع ولا كاميرا ولا جهات اتصال.**

## البناء

```bash
export ANDROID_HOME=/path/to/android-sdk   # يحتاج build-tools 35 و platforms/android-34
cd yassota/android
./build.sh
```

المخرجات: `YASSOTA-1.0.0.apk` في نفس المجلد، ويطبع السكربت الحجم والإصدار و**بصمة SHA-256**.

> **مهم — `build-tools 35` أو أحدث.** الإصدار 34 وما دونه يحتوي `d8` ينهار على الفئات المجهولة (anonymous inner classes) تحت JDK 21، وهو نفس الخطأ الذي واجهناه في تطبيق ShamHost بهذا المستودع.

لتغيير الإصدار:
```bash
VERSION_NAME=1.1.0 VERSION_CODE=2 ./build.sh
```

## التوقيع والأسرار

- عند أول بناء يُولَّد مفتاح إصدار `yassota-release.jks` وكلمة مروره في `keystore.properties`.
- **الاثنان مستبعدان من git** عبر `.gitignore` (`*.jks`, `*.keystore`, `keystore.properties`).
- **خُذ نسخة احتياطية آمنة منهما.** فقدان المفتاح = استحالة إصدار تحديث لنفس التطبيق على الأبد.
- في CI استخدم أسراراً بدل الملف:
  ```bash
  YASSOTA_KEYSTORE=/secure/yassota.jks YASSOTA_KS_PASS="$KS_SECRET" ./build.sh
  ```

## بعد البناء — خطوتان إلزاميتان

`build.sh` يطبع البصمة جاهزة. ضعها في:

1. **`yassota/.well-known/assetlinks.json`** — استبدل `REPLACE_WITH_RELEASE_SHA256_FINGERPRINT`.
   بدونها لن يتحقّق أندرويد من App Links ولن تفتح الروابط داخل التطبيق.
2. **لوحة الإدارة** `/admin` ← تطبيق أندرويد ← حقل SHA-256 (مع الإصدار والحجم ورابط التحميل).
   عندها تعرض صفحة `/apps/yassota` البيانات تلقائياً ليتحقّق المستخدمون من أصالة الحزمة.

## عن تحذيرات التثبيت

عند التثبيت خارج Google Play يعرض أندرويد تحذيراً معتاداً لمصادر التثبيت. **لا نتحايل عليه** — لا إخفاء لهوية التطبيق ولا تغيير لاسم الحزمة ولا تعطيل لـPlay Protect. بدل ذلك: توقيع إصدار حقيقي، HTTPS، نطاق رسمي، اسم حزمة ثابت، وبصمة SHA-256 منشورة ليتحقّق منها أي مستخدم. الحل النهائي للتحذير هو النشر على Google Play.

### ⚠️ نسخة احتياطية من مفتاح التوقيع

`yassota-release.jks` و`keystore.properties` مُولَّدان في بيئة مؤقتة **تُمحى عند انتهاء الجلسة**، وهما مستبعدان من git عمداً. بدونهما لا يمكن إصدار أي تحديث لنفس التطبيق إلى الأبد. احفظ نسختك منهما في مكان آمن قبل إغلاق الجلسة.
