# ShamHost — حوّل جوالك إلى استضافة ويب كاملة

نظام استضافة يعمل على جهاز أندرويد عبر **Termux**، **بدون روت**، مع لوحة تحكم عربية شبيهة بـ cPanel،
وأتمتة كاملة لربط دومين **Namecheap** وإصدار شهادات SSL ونشر الموقع على الإنترنت.

---

## قبل أي شيء: حقيقة موضوع cPanel

**cPanel الأصلي لا يمكن تشغيله على أندرويد، لا بروت ولا بدونه.** هذه ليست مسألة مهارة أو حيلة تقنية:

| المتطلب | cPanel الرسمي | جهازك |
|---|---|---|
| نظام التشغيل | AlmaLinux / RHEL / Ubuntu Server | Android (نواة لينكس بمساحة مستخدم مختلفة) |
| المعمارية | x86_64 حصراً | ARM64 غالباً |
| الصلاحيات | root كامل + systemd | لا يوجد أي منهما في Termux |
| الترخيص | مدفوع وشهري ومربوط بـ IP | — |

أي موقع يعرض عليك "cPanel للأندرويد" فهو إما واجهة مقلّدة أو احتيال.

**ما يقدمه ShamHost بدلاً منه:** كل ما تستخدمه فعلياً من cPanel، مبنياً خصيصاً لبيئة Termux:

- إدارة المواقع والنطاقات الفرعية (بدل Domains / Subdomains)
- قواعد بيانات MariaDB ومستخدمين وصلاحيات (بدل MySQL Databases)
- مدير ملفات كامل: تصفح، تحرير، رفع، فك ضغط (بدل File Manager)
- شهادات SSL من Let's Encrypt (بدل SSL/TLS Status)
- مهام مجدولة (بدل Cron Jobs)
- نسخ احتياطي واسترجاع (بدل Backup Wizard)
- سجلات وإحصاءات (بدل Metrics / Errors)
- **واجهة برمجية متوافقة مع cPanel UAPI** — أي تطبيق يتكلم مع cPanel يعمل مع جهازك بلا تعديل سطر واحد

## المتطلبات

- جهاز أندرويد 7 فأحدث، ويُفضّل 3GB ذاكرة فأكثر ومساحة 2GB فارغة
- **Termux من F-Droid** — نسخة Google Play قديمة ومكسورة ولن تعمل
  https://f-droid.org/packages/com.termux/
- (اختياري لكن مهم) **Termux:Boot** لتشغيل الخادم تلقائياً بعد إعادة تشغيل الجهاز
- (اختياري) **Termux:API** لقراءة حالة البطارية داخل اللوحة
- اتصال إنترنت أثناء التثبيت

## التثبيت

### الطريقة الأسهل: أمر واحد

في Termux على **جهاز الاستضافة** (الجوال الآخر):

```bash
curl -fsSL https://raw.githubusercontent.com/shwybs3/sham/claude/web-app-hosting-domain-1enxch/termux-host/bootstrap.sh | bash
```

يجلب المشروع ويشغّل المثبّت كاملاً. آمن لإعادة التشغيل: يحدّث نسخة موجودة ويحافظ على إعداداتك وكلمة مرورك.

### أو من داخل التطبيق

ثبّت `ShamHost.apk` على جهاز الاستضافة واضغط **تثبيت ShamHost على هذا الجهاز** — يرسل التطبيق الأمر أعلاه إلى Termux ويعرض لك التنفيذ مباشرة. لا حاجة لكتابة أي شيء.

### أو يدوياً

```bash
pkg install -y git
git clone -b claude/web-app-hosting-domain-1enxch https://github.com/shwybs3/sham.git
cd sham/termux-host
bash install.sh
```

يستغرق التثبيت من 5 إلى 15 دقيقة. في النهاية ستُطبع كلمة مرور اللوحة **مرة واحدة فقط — احفظها**.

ثم من أي جهاز على نفس شبكة الواي فاي، افتح المتصفح على:

```
http://عنوان-الجوال:8088
```

العنوان مطبوع في نهاية التثبيت، ويمكنك استرجاعه في أي وقت بالأمر `shamhost url`.

> إن ظهر لك `bash: shamhost: command not found` فمعناه أن ShamHost لم يُثبَّت بعد على هذا الجهاز —
> نفّذ أمر التثبيت أعلاه أولاً. وإن ظهر `ERR_CONNECTION_REFUSED` على المنفذ 8088 فالخدمة متوقفة:
> نفّذ `shamhost start`.

## تطبيق أندرويد (APK)

بدل فتح المتصفح وكتابة العنوان في كل مرة، ثبّت `termux-host/android/ShamHost.apk` على جوالك:

- **على جوالك الشخصي**: يفتح اللوحة مباشرة، وفيه **بحث تلقائي** يفحص الشبكة ويجد الجوال المستضيف بلا كتابة IP.
- **على الجوال المستضيف**: يضيف شاشة تحكم تشغّل وتوقف الخدمات بضغطة، عبر واجهة `RUN_COMMAND` الرسمية في Termux.

التفاصيل وطريقة البناء من المصدر: [`android/README.md`](android/README.md)

## أول موقع في 60 ثانية

1. افتح اللوحة ← **النشر الآلي**
2. اكتب الدومين واختر النوع (PHP / ملفات ثابتة / تطبيق Node)
3. فعّل «إنشاء قاعدة بيانات»
4. اختر طريقة النشر: **نفق Cloudflare مؤقت** للتجربة الفورية
5. اضغط **ابدأ النشر الآلي**

سيتولّى المعالج: إنشاء الموقع ← تجهيز nginx ← إنشاء قاعدة البيانات والمستخدم ← فتح نفق إلى الإنترنت ← إصدار SSL،
ويعرض لك سجل التنفيذ خطوة بخطوة مع بيانات الاتصال بقاعدة البيانات.

ارفع ملفات موقعك بعدها من **مدير الملفات**، أو مباشرة إلى المجلد:
`~/.shamhost/sites/اسم-الموقع/`

## نشر الموقع على الإنترنت — أي طريقة تختار؟

الجوال لا يملك عادةً عنوان IP عاماً (شبكات الجيل الرابع والخامس خلف CGNAT)، ولا يمكنه فتح المنفذين 80 و443 بدون روت.
لذلك أمامك ثلاث طرق مرتّبة من الأفضل للأصعب:

### 1. نفق Cloudflare دائم (الموصى به بقوة)

يعطيك HTTPS حقيقياً على دومينك، بدون IP ثابت وبدون لمس إعدادات الراوتر.

1. انقل دومينك إلى خوادم أسماء Cloudflare (مجاناً) — من اللوحة: **الدومينات ← خوادم الأسماء**
2. من `one.dash.cloudflare.com` ← Networks ← Tunnels ← Create a tunnel ← Cloudflared
3. انسخ **Tunnel Token**
4. أضف **Public Hostname**: دومينك ← `http://localhost:8080`
5. في اللوحة: **الأنفاق** ← نوع «دائم» ← الصق الرمز ← تشغيل

### 2. نفق مؤقت

رابط `*.trycloudflare.com` فوري بدون أي حساب. ممتاز للاختبار، لكنه يتغير عند كل إعادة تشغيل.

### 3. ربط مباشر بـ IP عام

يصلح فقط إذا كنت على إنترنت منزلي بعنوان عام وتستطيع توجيه المنافذ:
وجّه في الراوتر المنفذ 80 إلى 8080 والمنفذ 443 إلى 8443 نحو عنوان الجوال المحلي،
ثم من اللوحة: **الدومينات ← ربط سريع ← استخدم IP جهازي**.
وإذا كان العنوان متغيّراً، استخدم قسم **DNS الديناميكي** في نفس الصفحة.

## ربط دومين Namecheap

راجع الدليل التفصيلي: [`docs/NAMECHEAP.md`](docs/NAMECHEAP.md)

باختصار: فعّل API من حسابك، أدرج IP جهازك في القائمة البيضاء، أدخل المفتاح في **الإعدادات**،
ثم استخدم **الدومينات و DNS** لإضافة السجلات أو تعديلها.

اللوحة تقرأ السجلات الحالية وتدمج تعديلك قبل الإرسال، لأن واجهة Namecheap تستبدل كل السجلات دفعة واحدة —
وهذا خطأ شائع يمحو DNS كامل لمن يستدعي الواجهة مباشرة.

## شهادات SSL

من **شهادات SSL** ← اختر الدومين ← **Let's Encrypt**.

يستخدم النظام تحدي **DNS-01** عبر Namecheap، وهو الطريقة الوحيدة العملية هنا لأن تحدي HTTP-01 يحتاج المنفذ 80
الذي لا يمكن فتحه بدون روت. يعمل التجديد التلقائي عبر `acme.sh`.

عند استخدام نفق Cloudflare يكون HTTPS متوفراً عند حافة الشبكة أصلاً، ولا تحتاج شهادة محلية.

## واجهة متوافقة مع cPanel UAPI

هذا المستودع يحتوي على `syria-home/includes/cpanel/CPanelClient.php` الذي يتحدث مع cPanel حقيقي.
ShamHost يوفّر واجهة بنفس الشكل، فيكفي تغيير المضيف والرمز في الإعدادات ليعمل الكود كما هو:

```
GET http://عنوان-الجوال:8088/execute/SubDomain/addsubdomain?domain=blog&rootdomain=example.com
Authorization: cpanel admin:الرمز
```

الرمز من: **الإعدادات ← واجهة متوافقة مع cPanel ← إظهار الرمز**.

الدوال المدعومة:

| الوحدة | الدوال |
|---|---|
| SubDomain | `addsubdomain` · `delsubdomain` · `list_subdomains` |
| Mysql | `create_database` · `create_user` · `set_privileges_on_user` · `list_databases` · `list_users` · `delete_database` |
| DomainInfo | `list_domains` |
| StatsBar | `get_stats` |

الردود بنفس بنية UAPI: `{"status":1,"data":…,"errors":null}`.

## أوامر الطرفية

```
shamhost start          تشغيل كل الخدمات
shamhost stop           إيقافها
shamhost restart        إعادة تشغيل
shamhost status         حالة الخدمات والروابط
shamhost logs [panel|nginx|php|mariadb]
shamhost password [كلمة] تعيين كلمة مرور اللوحة
shamhost url            رابط اللوحة
shamhost reload         إعادة تحميل nginx بدون قطع
shamhost doctor         فحص شامل للمشاكل
shamhost service <اسم> <start|stop|restart>
```

## المنافذ والمسارات

| العنصر | القيمة |
|---|---|
| لوحة التحكم | 8088 |
| مواقع HTTP | 8080 |
| مواقع HTTPS | 8443 |
| PHP-FPM | 127.0.0.1:9000 |
| MariaDB | 3306 |
| مجلد العمل | `~/.shamhost/` |
| ملفات المواقع | `~/.shamhost/sites/` |
| السجلات | `~/.shamhost/logs/` |
| النسخ الاحتياطية | `~/.shamhost/backups/` |
| الإعدادات والأسرار | `~/.shamhost/data/config.json` (صلاحيات 600) |

المنافذ أقل من 1024 محجوزة للروت في لينكس، ولهذا لا يعمل الخادم على 80 مباشرة.

## الأمان — اقرأ هذا

- اللوحة تستمع على كل الشبكات افتراضياً لتصل إليها من جوالك الآخر. **على شبكة عامة غيّر ذلك**:
  الإعدادات ← ربط اللوحة بـ `127.0.0.1` واستخدم `ssh -L` للوصول.
- كلمة المرور مخزّنة كتجزئة PBKDF2 بـ 120 ألف دورة، وتُقفل المحاولات بعد 6 إخفاقات لمدة 10 دقائق.
- الجلسات ملفات تعريف `HttpOnly` + `SameSite=Strict`، وكل طلب مُعدِّل يتطلب ترويسة حماية إضافية.
- صفحة **الطرفية** تنفّذ أوامر بصلاحيات مستخدم Termux. لا تفتح اللوحة لأشخاص لا تثق بهم.
- مفتاح Namecheap API يمنح تحكماً كاملاً بـ DNS دوميناتك. احتفظ بنسخة من `config.json` في مكان آمن، ولا تشاركه.
- **لا ترفع `~/.shamhost/data/config.json` إلى GitHub.**

## بيئة لينكس معزولة (Debian كامل داخل Termux)

إن أردت بيئة أقرب إلى خادم لينكس حقيقي — نظام Debian كامل، `apt`، أسماء حزم
قياسية، مسارات `/etc` و `/var` المعتادة — أو عند تعذّر ترويت الجهاز، شغّل:

```bash
bash proot-setup.sh
```

يبني هذا نظام ملفات **Debian حقيقياً معزولاً** عبر `proot-distro` فوق نواة أندرويد،
**بدون root فعلي** (يحاكيه proot)، ويثبّت فيه مكدس LEMP كامل (nginx + php-fpm +
MariaDB). بعده:

```bash
shamhost-proot start     # يشغّل الخدمات داخل البيئة المعزولة
# ثم افتح: http://127.0.0.1:8080/
shamhost-proot           # للدخول إلى صدفة البيئة المعزولة
```

**صريح عن cPanel:** cPanel/WHM الرسمي **لا يعمل هنا** — يتطلب root حقيقياً و
systemd وتوزيعة RHEL وترخيصاً مدفوعاً مربوطاً بـ IP، ولا يتوفر أيٌّ منها على جوال
بلا روت. ما تحصل عليه هو **مكافئ وظيفي**: بيئة معزولة قوية تدير مواقعك عبر لوحة
ShamHost (التي تغطي ما يُستخدم فعلياً من cPanel) أو يدوياً من `/srv/www`. أي أداة
تَعِدك بـ «cPanel كامل حرفياً» على جوال بلا روت تُضلّلك.

## القيود الواقعية

هذا خادم حقيقي، لكنه يعمل على جوال. كن واقعياً في التوقعات:

- أندرويد يقتل العمليات الخلفية بعدوانية. `termux-wake-lock` يُفعَّل تلقائياً، ويجب استثناء Termux من تحسين البطارية يدوياً من إعدادات النظام.
- التشغيل المستمر مع اتصال شبكة يستهلك البطارية ويرفع الحرارة. اترك الجهاز على الشاحن مع تهوية.
- شبكة الجيل الرابع/الخامس تقطع الاتصالات الخاملة. نفق Cloudflare يعيد الاتصال تلقائياً؛ الربط المباشر بـ IP لا يفعل.
- مناسب لموقع شخصي أو مدونة أو واجهة API خفيفة. غير مناسب لمتجر بآلاف الزوار يومياً.
- تخزين الجوال بطيء نسبياً في العمليات المتزامنة؛ لا تتوقع أداء VPS.
